## Execution protocol

Freeze interfaces in S0 before parallel work. Each slice includes tests and evidence; no giant all-at-once migration. One executor owns `store.py`/schema changes at a time; contract changes reviewed by affected owners first. Existing native roles: `planner` slices, `architect` boundaries, `executor` scoped production changes, `test-engineer` adversarial fixtures, `code-reviewer` independent safety review, `verifier` final measured claims; use higher scrutiny on jobs/egress/grants, normal bounded implementation on UI. Executors are not alone and must not revert others. Use `$ultragoal` after durable user-authorized handoff; optionally `$team` only when durable parallel lanes justify overhead, with root owning integration/goals/ledger and independent verifier returning evidence. No fabricated goal/runtime authority if binding is unavailable.

## Cross-slice release evidence and stop rules

Every slice reports changed resources, command outputs/test counts, model/schema versions, known gaps and rollback state. Preserve existing68Python/73Node regressions, add mypy configuration and targeted/browser test entrypoints instead of claiming nonexistent tools passed. **A outcome:** user can produce and inspect a company/exact-role-grounded reviewed application in one local Python UI; all provenance and quality gaps visible. **B:** safe supported-form preparation with explicit transmission consent. **C:** exact final user approval, one attempted action and honest receipt/unknown state. Completion requires fresh independent verification for that milestone. Each milestone can stop without implementing the next; failure in later browser support must not disable useful A export workflow.
