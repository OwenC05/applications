## Outcome, constraints and evidence
Deliver a separate local Python evidence workbench: explicitly import synthetic/user-selected TXT/MD/text-PDF, inspect exact source quotations, explicitly confirm reusable facts, retrieve through Chroma dense + bm25s + RRF + local cross-encoder, and inspect integrity-checked citations. Raw-source search is never applicant-confirmed evidence. No generated answers or hiring-quality promises in this milestone.

Baseline `49fede5`: Node app `src/`, `public/`, `test/`, `API.md` remains unchanged; package scripts provide `npm test` and `npm run check`. New implementation under `backend/`, `eval/`, root Docker files and additive README section. No reads/imports of `.env`, `.data`, CVs or coursework. Separate data root and loopback port 3001 avoid the existing Node port3000. Profiles are convenience scopes, not security against other local users/processes. Single installation, English-first, CPU-only.

Environment intake reports Python3.14, no uv/Docker; host7.6GiB RAM (~3.9GiB available),2GiB swap,/tmp3.8GiB free. Use Linux-home caches for isolated venv/models, bounded real smoke; no hardware promise. After execution authorization, provision isolated Python3.12 and resolve locked CPU-compatible dependencies. Do not silently substitute fake vectors or omit a retrieval stage. Docker execution remains a disclosed verification gap if daemon unavailable.

## RALPLAN-DR / decision
Principles: (1) confirmed text, not persuasive inference, is application evidence; (2) SQLite owns truth, indexes are disposable; (3) deletion/ownership checks outrank stale retrieval; (4) small reversible parallel slices; (5) measured verification, not production labels.

Three drivers: end-to-end inspectable evidence; privacy/integrity under interruption; runnable progress without destroying the existing usable MVP.

A — selected: separate evidence backend/workbench, one API process, synchronous bounded operations with serialized mutation/index build, staging manifests and persistent cleanup records. Pros: isolated migration risk, immediately exercisable provenance/retrieval, small surface. Cons: blocking build UX, no durable long-running job recovery, later UI/API integration work. Limit this milestone to 1000 indexed chunks/profile, 10MB/upload, 100 PDF pages, 1M extracted characters, 30s extraction deadline. Build/retrieval resource failures return actionable errors, never partial success.

B — full Node parity and durable worker first: preserves one user experience and enables long operations/retries early. Costs broad domain migration, larger review surface, delays proving mandated retrieval. Viable next milestone, not rejected as inherently bad. Do not half-build a queue inside A: failed builds stay unpublished, explicit rebuild retries; no cloud operations exist.

C — CLI-only evidence library: simplest automated verification and smallest attack surface; insufficient friend-facing usable milestone. Retain CLI smoke/setup utilities, not sole delivery.

## Frozen cross-lane contract (root publishes types before parallel work)
Root owns `backend/copilot/contracts.py`; dataclasses or Pydantic models with immutable records, snake_case JSON, UUID identifiers and UTC timestamps. Typed `EvidenceError(code, safe_message, http_status)`; stable codes NOT_FOUND, INVALID_INPUT, CONFLICT, INDEX_NOT_READY, MODEL_NOT_READY, LIMIT_EXCEEDED, CLEANUP_PENDING. Foreign IDs behave as NOT_FOUND.

- `Profile(id, name, sectors: list[Literal['tech','finance']], revision:int)`.
- `Source(id, profile_id, filename, media_type, blob_sha256, parser_version, state: active|deleting|deleted)`; immutable source version ID is `id`; no in-place text replacement.
- `Unit(id, profile_id, source_id, ordinal:int, page:int|None, text:str, text_sha256:str)`. TXT/MD is one normalized canonical unit (CRLF/CR→LF, otherwise preserve Unicode/whitespace); PDF one canonical text unit per physical page, 1-based. Hash SHA256 of UTF8 canonical text. Offsets are Python Unicode code-point indices, zero-based/end-exclusive. Compute 1-based TXT/MD line locations from canonical text at resolve time. Never use byte/token offsets as character offsets.
- `Span(unit_id, start:int, end:int)`; `0 <= start < end <= len(unit.text)`.
- `Fact(id, profile_id, text, text_sha256, confirmed_at, provenance:manual|document_derived, origin:Span|None, state:active|revoked|superseded)`. Confirmation accepts an explicit `confirmed:true`; edit creates new ID/version and supersedes old atomically. Origin is labelled proposal origin, not semantic proof. No pending/raw content indexed in fact corpus.
- `Chunk(id, profile_id, corpus:facts|documents, record_id, unit_id:str|None, start,end,text,text_sha256)`; facts use record_id=fact ID and unit_id=None, spans in canonical fact text. Source chunks record_id=source ID. Stable ID hashes owner/corpus/record/unit/span/text hash/chunker version. Embedding tokenizer provides offsets, preserving canonical slices; maximum input includes special tokens and is validated against pinned model limit. No reconstructed text from token decoding.
- `Snapshot(profile_id, corpus, revision:int, chunks:tuple[Chunk,...])`. Capture only currently active eligible records; revision increments for canonical changes/revocations. Documents snapshot includes all active documents; query selection is mandatory and filtered BEFORE both branch ranking, not merely after top-k.
- `Manifest(generation_id, profile_id, corpus, revision, model_fingerprint, chunker_version, chunk_ids_sha256, chunk_count, dense_collection, sparse_relpath, state:staging|active|retired)`. Both branches derive from identical sorted IDs; include ID-set/checksum validation. One active manifest per owner/corpus; empty corpus returns explicit empty result without fabricating a branch.
- `Citation(profile_id, corpus, record_id, unit_id, start,end,text_sha256,excerpt)` hash binds full canonical unit/fact text; excerpt must equal canonical slice. API does not trust profile_id from citation over route scope.
- `Hit(chunk:Chunk, citation:Citation, dense_rank:int|None, bm25_rank:int|None, rrf_score:float, rerank_score:float)`; relevance scores are not support probabilities.

Storage public interface (`store.py`, lane S): `Store(data_dir:Path)`; `create_profile(name,sectors)->Profile`; `list_profiles()->list[Profile]`; `list_sources(profile_id)->list[Source]`; `list_units(profile_id,source_id)->list[Unit]`; `read_source(profile_id,source_id)->bytes`; `list_facts(profile_id)->list[Fact]`; `add_source(profile_id, filename, media_type, original:bytes, units:list[str], parser_version)->Source`; `confirm_fact(profile_id,text,origin:Span|None=None,supersedes:str|None=None)->Fact`; `snapshot(profile_id,corpus,chunker:Callable[[Unit|Fact],list[Chunk]])->Snapshot`; `publish_manifest(manifest,expected_revision:int)->None`; `active_manifest(profile_id,corpus)->Manifest|None`; `validate_snapshot(profile_id,revision:int)->None`; `eligible_chunks(profile_id,corpus,chunk_ids:list[str],source_ids:list[str]|None)->list[Chunk]`; `citation_for_chunk(profile_id,chunk)->Citation`; `resolve_citation(profile_id,citation)->dict`; `revoke_fact(profile_id,fact_id)->CleanupTicket`; `delete_source(profile_id,source_id)->CleanupTicket`; `delete_profile(profile_id)->CleanupTicket`; `pending_cleanup()->list[CleanupTicket]`; `complete_cleanup(ticket_id)->None`. Read/publish methods transactionally scope owner; `snapshot` transactionally persists canonical chunks at its captured revision. `citation_for_chunk` derives the full canonical unit/fact hash, never the chunk-excerpt hash. Root and S resolve any signature refinements before lane R starts, in one shared contract amendment, not competing ad-hoc implementations.

Ingestion (`documents.py`, S): `ingest(store,profile_id,filename,media_type,content:bytes)->Source`; UTF8 TXT/MD and pypdf text extraction in a killable Linux subprocess with RLIMIT_AS512MiB, CPU-time cap and30s wall deadline plus byte/page/character ceilings; unsupported resource-limit platforms fail PDF parsing explicitly, never claim an unenforced cap; no shell, embedded execution or automatic URL fetching. Reject malformed/encrypted/scanned/no-text/unsupported input. Stage original bytes until validated; clean failure files. Persist hash/parser identity and units atomically.

Retrieval (`retrieval/service.py`, R): `EvidenceService(store, index_root:Path, dense:DenseIndex, models:LocalModels)`; `build(profile_id,corpus)->Manifest`; `search(profile_id,corpus,query,source_ids:list[str]|None=None,limit:int=8)->list[Hit]`; `cleanup(ticket:CleanupTicket)->None`. Explicit `DenseIndex` adapter real Chroma HTTP for deployed mode, PersistentClient allowed only integration tests; injected test doubles never accepted as real-model evidence. LocalModels implements `tokenize_offsets`, `embed(list[str])`, `rerank(query,list[str])`, fingerprint. Candidate branch30 each, RRF k60, fused40, max8 final; tie-break by chunk ID; cap query tokens and passage pairs explicitly with truncation metadata.

`CleanupTicket(id, profile_id, generation_ids:list[str], source_ids:list[str], fact_ids:list[str], state:pending|complete)` is persisted metadata, not a generic job queue. Canonical tombstones commit first, increment revision and invalidate affected manifests immediately. Simplest safe cleanup removes all owner index generations plus relevant blobs/chunks/canonical content and linked fact content. A source delete revokes linked facts, never silently preserves them; standalone reconfirmation is a later explicit action. Fact revoke leaves original document searchable and UI discloses that distinction. Complete only after canonical queries cannot retrieve deleted content, owned blob/sparse files are removed, Chroma API confirms collection absence, and process caches are evicted; failure retains pending ticket, boot runs cleanup before index readiness. This verifies application-level logical deletion and owned-file removal, not forensic erasure of SQLite WAL/freelists, Chroma storage remnants, SSDs, host RAM or backup media. UI/docs disclose plaintext local storage and these forensic limits. Content-free tombstones survive. Historical pending tickets remain scope-readable after profile deletion. Cleanup operations idempotent, interrupted cleanup resumes; no background stale writer can publish against changed revision.

Operational constraint: long builds run explicit CLI, not an HTTP task or pseudo-job. Root serializes CLI build/API confirm/revoke/delete and final search/citation response checks with an OS interprocess lock on the private data root; deploy one API worker, no reload. Interrupted build cleanup removes orphan staging before readiness; successful later writes cannot resurrect deleted versions. SQLite conditional revision publication still required to protect restart/staging and tests. Search reads one manifest; verify both branches/fingerprint/ID sets, reject stale or partial state, check selected-source ownership before retrieval and final eligibility/revision before response. On concurrent change return CONFLICT/rebuild-needed rather than stale text. SQLite is authoritative even if a stale Chroma hit exists. No raw text in logs.

## Three pre-mortems and mitigations
1. Accurate citation badge is mistaken for truthful candidate claim. Separate raw/fact modes and explicit confirmation; immutable corrected fact provenance, quote-only UX, score disclaimers; adversarial corrected-number/adjacent-unconfirmed fixtures.
2. Deleted data resurfaces from stale BM25/Chroma or interrupted build. Revocation-first transaction, invalidated manifests, final eligibility, revision CAS, both-branch checks, persistent cleanup ticket and restart fault injection; deletion status never lies.
3. Friend setup stalls on huge downloads/incompatible wheels/Docker absence. Isolated3.12, CPU lock, explicit pinned model setup and actionable readiness, two retrieval smoke levels and honest unrun Docker gap. No full production/local-performance claims without measurements.
